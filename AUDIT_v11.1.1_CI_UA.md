# CI та зовнішні бібліотеки — Max Camera Distance v11.1.1

## Правильна модель збірки

Вихідний репозиторій **не містить** копій LibStub, CallbackHandler-1.0, AceDB-3.0, LibDataBroker-1.1 та LibDBIcon-1.0. Вони описані в секції `externals` файлу `.pkgmeta` і завантажуються **тільки на етапі пакування** через BigWigsMods/packager. Це відновлює структуру наданого архіву.

У вихідному `libs/` лишаються **лише** `libs/_manifest.xml` та власна змінена `libs/LibCamera/` (її не можна автоматично замінювати зовнішнім релізом).

## Перевірки CI

1. **Вихідний код:** `python3 tools/verify_manifest.py --allow-missing-externals` допускає відсутні скрипти тільки всередині каталогів, оголошених як externals у `.pkgmeta`. Немає загального ігнорування `libs/`, тому відсутня `LibCamera` або помилка в іншому XML зупинить CI.
2. **До пакування:** `bash check_all.sh` проводить статичні, регресійні та fallback-тести без вимоги попереднього завантаження зовнішніх бібліотек.
3. **Збірка:** `BigWigsMods/packager@v2` із `-d` створює ZIP і завантажує всі зовнішні бібліотеки до `.release/Max_Camera_Distance/libs/`.
4. **Готовий пакет:** `tools/verify_package.py` суворо перевіряє всі XML-посилання, наявність і непорожність скриптів, незмінність власних файлів (з допуском LF/CRLF) та повний збіг ZIP з перевіреним деревом.
5. **Після пакування:** із `MCD_PACKAGED_ROOT` запускаються повні Lua 5.1-матриці включно з режимом `embedded`, в якому бібліотеки читаються саме з готового дерева релізу. Додатково перевіряється Lua-синтаксис файлів із готового релізу.
6. **Публікація:** тільки після успішних перевірок, без повторного checkout externals (`-o -c -e`).

## Локальні команди

```bash
python3 tools/verify_manifest.py --allow-missing-externals
python3 tests/probe_package.py
bash check_all.sh
# Після пакування:
python3 tools/verify_manifest.py --root .release/Max_Camera_Distance
python3 tools/verify_package.py --root .release/Max_Camera_Distance --archive .release/Max_Camera_Distance-v11.1.1.zip
MCD_PACKAGED_ROOT="$PWD/.release/Max_Camera_Distance" bash check_all.sh
```

Звичайна команда `python3 tools/verify_manifest.py` без `--allow-missing-externals` залишається **строгою** і в чистому вихідному коді очікувано виявляє відсутні до складання файли. GitHub Actions використовує правильний режим на кожному етапі.

## Відомі обмеження

Залежності позначені `.pkgmeta` як `tag: latest`, тобто версії не зафіксовані на конкретному коміті. Перевірка існування файлів і синтаксису не замінює перевірку змісту зовнішнього коду та запуску в реальному WoW. Віддалений GitHub Actions у цій робочій сесії не запускався.

## Hotfix перевірки релізу (09.10.2026)

- Виправлено помилкове порівняння бібліотек із `.pkgmeta` з файлами, раніше завантаженими іншим CI-скриптом: тільки BigWigs packager визначає зовнішні бібліотеки.
- Прибрано хибні SHA-256 для бібліотек, які надходять з іншого upstream/tag. Перевірка гарантовано звіряє весь готовий ZIP із staging-каталогом побайтово, але **не** гарантує автентичність зовнішнього репозиторію. Для останнього потрібно фіксувати зовнішні ревізії та перевірені суми для тих самих байтів.
- Невідомий `steps.package.outputs.archive_path` замінено пошуком рівно одного `.release/Max_Camera_Distance-*.zip`; порожній або неоднозначний шлях тепер блокує реліз.
- Збережено сувору перевірку `_manifest.xml`, локальної `LibCamera`, а також фактичних Lua-бібліотек після пакування.
- Важливо: назву релізу packager бере з Git-тега, а не лише з TOC. Якщо запущено тег `v11.0`, буде `v11.0.zip` попри версію `v11.1.1` у вихідному TOC.
