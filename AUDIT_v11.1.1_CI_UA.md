# Виправлення CI — Max Camera Distance v11.1.1

У наданому логу провалено три етапи: Manifest references, LibCamera ranges і native settings matrix.
Не знайдено LibStub, CallbackHandler, AceDB, LibDataBroker, LibDBIcon та старий LibMountInfo.
LibCamera-файл існує, але не реєструє приватний major, який очікує наш код і тест.

## Причина й виправлення

- CI запускав строгий check_all.sh до пакувальника, тоді як .pkgmeta описував бібліотеки як externals, що завантажуються пізніше.
- Саме зниження помилок маніфесту до warning не виправляє відсутні бібліотеки в runtime-тестах.
- У поточному архіві всі потрібні бібліотеки присутні. Після виправлення source-check допускає, що частина `libs/` не потрапила в Git checkout: окремий CI-крок відновлює п'ять сторонніх бібліотек за `DEPENDENCIES.json`, перевіряє SHA-256, і лише тоді запускає Lua-тести. З `.pkgmeta` прибрано неконтрольовані `latest` externals.
- libs/_manifest.xml містить шість наявних бібліотек. LibMountInfo не є обов’язковим завантажуваним файлом; його старе посилання з наданого логу відсутнє.
- LibCamera зберігає приватний major MaxCameraDistance-LibCamera-1.0. Треба перенести весь libs/, включно з LibCamera і маніфестом, а не лише Config/SettingsWindow.
- CI перевіряє посилання вихідного маніфесту поза `libs/`, відновлює відсутні залежності (без заміни локального LibCamera), перевіряє повний маніфест і SHA-256, запускає Lua-тести, збирає пакет без upload, перевіряє його папку та ZIP, запускає LibCamera probe зі зібраної папки й лише тоді дозволяє публікацію.
- Upload повторно використовує перевірену папку без копіювання вихідного коду чи завантаження externals.
- Fallback версії більше не відкидає patch-номер. Для tag workflow береться поточний GITHUB_REF_NAME.

- Реальний BigWigs release.sh, режим без upload: успішно створено Max_Camera_Distance-v11.1.1.zip.
- verify_package.py: кожен завантажуваний XML/Lua-файл відповідає перевіреному вихідному коду, з урахуванням допустимого LF/CRLF. Файли ZIP побайтово збігаються зі зібраною папкою.
- LibCamera probe із фактичної зібраної папки: PASS.
- Повторне пакування з reuse-параметрами й вимкненим upload: PASS; перевірка ZIP повторно пройдена.
- Негативні регресії: видалений LibStub, стара реєстрація LibCamera, застарілий ZIP, зайві файли та відсутній ZIP відхиляються. Коректна CRLF-версія проходить.

## Використання

Для GitHub перенесіть весь вміст папки Max_Camera_Distance з цього архіву в корінь репозиторію, включно з libs/, tools/, tests/, .pkgmeta та .github/workflows/package.yml. Збережіть сторонні зміни свого репозиторію.
Для гри замініть папку Interface/AddOns/Max_Camera_Distance; профілі в WTF не видаляйте.

GitHub Actions у вашому віддаленому репозиторії тут не запускався. Перевірено локально фактичний пакувальник і чистий checkout. Публікацій не виконувалося. Перевірка в живому клієнті WoW залишається окремою.

## Доповнення: розділення source/release перевірок (09.10.2026)

- Простий `python3 tools/verify_manifest.py` більше не видає помилки про libs/ до їх завантаження; інші відсутні файли залишаються помилкою.
- `--strict-libs` обов'язковий для зібраної папки адона. Повний пакет не пройде перевірку, якщо хоч одна бібліотека відсутня.
- `tools/fetch_libraries.py` є кроком завантаження **між** source-check і повним тестуванням. Якщо бібліотеки вже є в checkout, їх лише перевіряють за SHA-256, без перезапису.
- Модифікована `libs/LibCamera/LibCamera.lua` — локальна залежність, її неможливо безпечно відновити з незафіксованого upstream; вона має бути в репозиторії.
- `tools/verify_package.py` звіряє бібліотеки за SHA-256 із `DEPENDENCIES.json`, навіть якщо їх нема у вихідному checkout, і звіряє фактичний ZIP із вмістом збірки.
- Додано регресійний тест `tests/probe_manifest.py` і розширено `tests/probe_package.py` для відкладених залежностей.
