# Перевірка Max Camera Distance v11.0.0 — 09.10.2026

## Виявлено та виправлено

1. Вхідний архів мав XML-посилання на відсутні бібліотеки. Без стороннього Ace3
   налаштування не реєструвалися. Тепер бібліотеки профілів і мінікарти включені,
   а вікно налаштувань не залежить від AceConfig/AceGUI.
2. Старий UI відключав елементи в системних налаштуваннях Blizzard через хуки
   внутрішніх віджетів. Ці хуки вилучені; нове вікно використовує свої віджети.
3. Обгортки CVar вважали відсутність Lua-помилки успішним записом. Тепер перевіряється
   результат сучасного SetCVar, а для старого глобального setter без результату — прочитане
   значення. Відхилення сучасного API не обходиться глобальним alias.
4. LibCamera використовує спільну політику запису. Якщо тимчасовий cameraZoomSpeed
   змінити не можна, використовується базова плавна зміна дистанції.
5. Сховище профілів без AceDB підтримує вибір, створення, копіювання, видалення,
   скидання й оновлення стану камери. Скопійовані дані не посилаються на той самий об’єкт.
6. LibCamera використовує окремий LibStub major, щоб бібліотека іншого адона
   не підміняла наші виправлення та щоб наша копія не змінювала його бібліотеку.
7. UI створюється при першому відкритті, повторно використовує видимі рядки,
   відкладає пошук на 140 мс і не перебудовує контролі під час введення/перетягування.
8. Виправлено CI-префікс версії; всі XML-посилання перевіряються без винятків
   для відсутніх бібліотек. Видалено непотрібний скомпільований luac.out.

## Що перевірено автоматично

- Синтаксис усіх Lua-файлів у Lua 5.1, відсутність випадкових глобальних записів.
- Коректність XML, актуальність генерації TOC, існування кожного завантажуваного файлу.
- Регресії пізнього AceDB та збереження профілю при переході з автономного сховища.
- Наявні перевірки геймпада, плечової камери, згасання зсуву, володіння CVar,
  відновлення зовнішніх значень, синхронних CVAR_UPDATE, виходу з гри.
- Діапазони cameraZoomSpeed, перехід без зміни дистанції, окрема LibCamera
  і перехід до базового зуму при відхиленні запису швидкості.
- Дев’ять клієнтських випадків: Retail, PTR, Era, TBC, Wrath, Titan, Cata, Mists,
  Forever; кожен — без AceDB та з реальною включеною AceDB, всього 18 сценаріїв.
- У суворій моделі UI: створення/прив’язка контролів усіх розділів, прокрутка,
  пошук українською та англійською, disabled, профілі та підтвердження, малі екрани,
  повторне відкриття без збільшення кількості об’єктів.
- Відхилення SetCVar (false/nil), невідомі/read-only/locked/secure CVar,
  відсутність обходу через глобальний setter, відмова передавати secret аргументи.

Повний результат запуску — `tests/RESULTS.txt`.

## Межі перевірки

У цьому середовищі немає запущеного клієнта WoW. Моделі API не відтворюють реальний
рендеринг, taint, приховані зміни приватного клієнта Forever чи фактичну поведінку
камера/колізій. Перевірка не є обіцянкою відсутності помилок у всіх збірках.
Сумісність стосується сучасних сімейств клієнтів у README; оригінальні старі
клієнти та довільні приватні форки не включені до підтвердженої області підтримки.
Нове вікно має текстури/шрифти гри; графічну відповідність референсу потрібно оцінити в грі.

## Жива перевірка

1. Встановити папку з архіву; перевірити завантаження адона без стороннього Ace3.
2. Відкрити `/mcd config`, усі видимі розділи, пошук, прокрутку, dropdown і точне
   число. Перевірити Esc, перетягування та UI scale.
3. Створити тестовий профіль; перевірити копіювання, скасування підтвердження,
   скидання й повернення до попереднього профілю. Зробити `/reload` і перевірити збереження.
4. Порівняти `/mcd status` у звичайному стані, бою, на маунті, у формі друїда,
   транспорті, AFK і після зміни зони. Перевірити ручне колесо та Reactive Zoom.
5. Перевірити повернення зовнішніх CVar після вимкнення ActionCam та виходу з гри.
6. На Forever перевірити окрему область геймпада/туману; на Classic — приховування
   неіснуючих можливостей. Перевірити BugGrabber та повідомлення про protected API.
